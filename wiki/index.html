Android 11 及以上

ASB 应用沙盒

用工作资料运行独立的应用副本，按应用管理权限，并向接入 ASB 的应用提供自定义测试数据。

查找 managed-v 版本 ↗
  1. 安装 ASB，打开后点「创建工作资料」，按系统提示完成设置。
  2. 回到桌面，在「工作」标签中打开带公文包标记的 ASB。
  3. 用工作资料的商店安装应用，或在 ASB 中选择工作资料里的单文件 APK。分包应用请通过商店安装。

如果手机已经配置了工作资料，Android 可能拒绝创建新的资料。删除现有工作资料会删除其中的应用和数据。

权限策略

范围策略效果
工作应用阻止、穿透、授予管理应用已声明的运行时权限。穿透解除管理员的固定状态，后续按 Android 的权限规则处理。
工作应用暂停阻止应用正常启动，随时可恢复。
工作资料摄像头、截屏和录屏、复制到个人资料由 Android 工作资料策略执行。个别 ROM 或既有管理员策略可能限制可操作项。
测试接口阻止、自定义、穿透接入方按返回值处理焦点、应用列表、摄像头测试图片与文件文本。

工作资料内的普通文件读写继续受 Android 存储权限约束。应用可通过系统文件选择器读写用户选定、提供方允许写入的文件。焦点与原生应用列表由系统管理，测试接口可返回自定义结果。

录屏

Android 14 及以上可从工作版 ASB 发起录制。在系统选择器中选择「单个应用」，再选择有公文包标记的目标应用。选择器由 Android 提供，ASB 无法验证选择的应用属于工作资料，也无法在所有 ROM 上关闭整屏选项。

通知栏可停止录制，视频以无声 MP4 保存到工作资料的 Movies/ASB。受保护的窗口由 Android 遮蔽，工作资料的「禁止截屏和录制」策略会禁止在 ASB 发起录屏。

测试接口

在 ASB 中选择工作应用，开启「向此应用开放测试接口」，选择每项策略并保存。摄像头自定义策略需要先选取一张测试图片。

调用方在自己的 Manifest 中声明 Provider 可见性，然后按 mode 选择阻止、使用自定义值或回退到正常 Android API。

<queries>
  <provider android:authorities="io.github.z2bguoguo.asb.fixtures" />
</queries>
Uri uri = Uri.parse("content://io.github.z2bguoguo.asb.fixtures");
Bundle policy = getContentResolver().call(uri, "getPolicy", "focus", null);
String mode = policy.getString("mode");
参数自定义模式返回值
focusfocused，布尔值
appspackages，包名字符串数组
camerauri，可通过 openInputStream 读取的 PNG
filestext，文本字符串

使用调试 APK 时，Provider authority 改为 io.github.z2bguoguo.asb.debug.fixtures。

调用可能抛出 SecurityException。测试应用需要为接口不可用的情况提供自己的处理逻辑。mode 取值为 block、custom、passthrough。

构建与发布

推送会运行 Android 构建、Lint、Vite 构建并上传构建产物。在 managed-profile 分支的 Actions 构建中下载 ASB-wiki，解压后打开 index.html。

Android 正式版由 managed-v主.次.修订 标签触发。签名设置见 仓库 README。ASB 定期检查更新，有新版本时发出通知；下载后核对包名、版本和签名，由 Android 显示安装确认。

./gradlew :app:assembleDebug :app:lintDebug
cd wiki
npm ci
npm run build

Shizuku 连接状态可在「更新与诊断」中查看。工作资料、权限策略、安装和录屏均通过 Android 系统接口运行。
